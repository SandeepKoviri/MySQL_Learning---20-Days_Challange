VIEWS
=====
what is view
------------
view is a virtual table in MySQL, built from the result of a stored select statement. It looks and behaves like a regular table when you query it, you can select from it filtering and join it, but it does not store any data of it's own every time a view is queried, MySQL runs its underlying select statement against the real tables and returns the result.

why do we need views
--------------------
simplify complex queries: hide multi-table joins, subqueries and calculation behind a single, simple table like name.
reuse query logic: write a complex select once and reuse it anywhere, reports applications, dashboards without copy pasting SQL
data security: expose only specific columns or rows to certain users, without granting them access to full base table
different perspectives of the same data: different departments can have their own tailored views of the same underlying tables.
logic and independence : if the underlying table structure change slightly, you can often adjust just view definition and keep all dependent queries working changed
simplifying reporting: pre-package aggregations(total, averages, counts) into a view so business users can query them without knowing SQL


ADVANTAGES 
-----------
Security: restrict access to sensitive columns(e.g.: salary) or sensitive rows(only a user own department)
Simplicity: end users and applications interact with simple named virtual table instead of complex SQL
Reusability: one view definition can be used across many reports, applications
Consistency: business logic(calculation, filter) lives in one place, so results are always consistent
Maintainability: a business rule change only need to be made once, inside the view
Custom data presentation: rename or format columns and computed columns without touching the base table
no extra storage cost: a standard view stores no data --> only its query definition

CREATING VIEW
-------------
Syntax
------
create view view_name as
select columns
from tables 
where condition'

ALTERING VIEW
-------------
alter view view_name as
select new_columns
from new_tables
where new_condition'

DROPPING VIEW
-------------
drop view view_name;

or 

drop view if exists view_name;

Transactions
------------
def:
----
the process of combining all related operations into a single unit and executing them according to rule, "either all operations should succeed or none should succeed" is called transaction management

example: funds transfer 
consider a money transfer process between two accounts 

1.debit amount from the senders account
2.credit amount into the receiver's account

there are two types of transactions such as
1.local transaction
--------------------
in local transactions all operations of a transaction are executed on the same database.

example:
--------
funds transfer from one account to another account where both account belong to the same bank

2.global transaction
--------------------
in global transactions, operations of a transaction are executed on different database

example
-------
funds transfer from one account to another account where both accounts belong to different banks

ACID Properties
===============
A ------> Atomicity:   all or nothing
C ------> Consistency: the database remains in a valid state
I ------> Isolation:   transactions do not interface with each other
D ------> Durability:  committed changes are permanent
