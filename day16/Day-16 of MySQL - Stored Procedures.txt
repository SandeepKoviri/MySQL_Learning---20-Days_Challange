Stored Procedures
------------------
--> a stored procedure is a named, precompiled collection of one or more SQL statements that is stored inside the database and can be executed(called) whenever required. instead of sending a long block of sql code from an appicatiom every time, the application simply calls the procedure by name.

why use stored procedures:
--------------------------
performance : precompiled and cached by the database engine,so repeated execution is faster then sending raw SQL each time

Reusability: write the logic once, call it from many applications or scripts.

Security: users can granted execute permission on a procedure without granting direct ACCESSED TO THE underlying tables.

Reduced Network traffic: a single call statement replaces many lines of SQL sent over the network.

Maintainability:

Consistency:

CREATE PROCEDURE SYNTAX:
------------------------

DELIMITER //
CREATE PROCEDURE PROCEDURE_NAME(
	[IN|OUT|INOUT] PARAMETR_NAME DATA_TYPE,.......
)
BEGIN
	--------SQL STATEMENTS/LOGIC
	--------DECLARATIONS, CONDITIONS, LOOPS..ETC
END//
DELIMITER;

ADVANTAGES:
-----------
faster execution after compliation
reduced duplication sql
supports transactions, loops, conditions, variables, curors and exception handlers.
easy maintence.

DISADVANTAGES:
--------------
Debugging can be difficult
vendor specific syntax
complex procedures may become hard to maintain.

IN PARAMETER:
-------------
DEFINITION: AN IN parameter is used to pass a value into stored procedure.
	
The procedure can use the value, but changes made to the parameter inside the procedure not returned the caller.

syntax:
-------
DLIMITER
create procedure procedure_name(IN parameter_name datatype)
BEGIN
	sql statements
END //

OUT PARAMETER:
-------------
DEFINITION: AN OUT PARAMETER IS USED TO RETURN A VALUE FROM THE STORED PROCEDURE TO THE CALLER.
THE CALLER PROVIDES A VARIABLE TO RECEVIE THE RESULT

SYNTAX:
-------
CREATE PROCEDURE PROCEDURE_NAME(OUT PARAMETER_NAME DATATYPE)
BEGIN
SET PARAMTER_NAME = VALUE;
END
